# Habla

**Learn Spanish. Actually speak it.**

Habla is a Spanish-learning web app built around one question: *can the learner actually produce this sentence?* It combines a structured curriculum with per-item spaced repetition, active recall, listening, dictation, pronunciation practice, guided roleplays, and an optional AI conversation partner.

## Quick start

```bash
npm install
npm run dev          # http://localhost:5173
```

On first launch you can start fresh (onboarding + adaptive placement) or **explore a demo learner**. The demo is generated by running a simulated learner through the real engine for about four weeks, so its memory states, mistakes and analytics are genuine outputs of the algorithm.

### Optional: AI conversation partner

Free conversation (speaking stage 7) uses Claude through a small server, so the API key never reaches the browser:

```bash
npm run build
ANTHROPIC_API_KEY=sk-ant-… npm run server   # serves the app and /api on http://localhost:8787
```

During development, run `npm run server` alongside `npm run dev`; Vite proxies `/api` to port 8787. Without a key everything else works, and the UI says plainly that the AI partner isn't connected. Guided roleplays run entirely on-device.

## How it works

```
src/
  content/     Curriculum (2 levels, 12 units, 39 lessons), grammar concepts, scenarios,
               listening pieces, pronunciation modules, phrase bank, placement items,
               verb conjugator, syllabifier
  engine/      The learning engine — pure TypeScript with no React, fully tested
    memory.ts        Per-item memory state, spacing ladder, forgetting curve, mastery evidence
    answer.ts        Answer checking (token alignment: accents, typos, missing and wrong words), speech evaluation
    mistakes.ts      Error classification (ser/estar, "yo es", "estoy hambre", gender, voy a…) and pattern tracking
    exercises.ts     Exercise generation per item and skill, assistance fading, anti-cramming, smart-review follow-ups
    lesson.ts        Lesson builder: Learn → Understand → Recall → Produce → Speak → Use
    session.ts       Daily session builder: priority scoring, weakness-weighted time allocation, interleaving
    progress.ts      Skill profile, approximate CEFR estimate, measured retention
    conversation.ts  Guided roleplay state machine, conversation scoring, AI learner context
    placement.ts     Adaptive staircase placement
    gamification.ts  XP weighted toward speaking and production, consistency, achievements
    simulate.ts      Demo learner generator
  services/    Browser APIs: text-to-speech, speech recognition, microphone recording, AI client
  components/  Reusable UI (SpeakingRecorder, SpanishText, ConversationInterface, SkillMeter, …)
  pages/       Screens
server/        Static hosting + Claude conversation endpoint
```

**Memory model.** Every word and sentence has its own state: a spacing ladder (10 min → 1 d → 3 d → 7 d → 14 d → 30 d → 60 d…) scaled per item by how hard it is for this learner, answer speed, hint use and exercise difficulty. Retrievability follows a power forgetting curve. Recognition-only successes can't push an item far up the ladder; mastery requires evidence across recall, production, listening, speaking and a long-delay recall.

**What's real, and what isn't.**
- Speech recognition and text-to-speech use the browser's Web Speech APIs. Pronunciation is judged by intelligibility: whether each target word was understood, not by accent. There is no phoneme-level scoring. `SpeechEvaluation` in `engine/answer.ts` is the boundary where a dedicated pronunciation service would plug in.
- In browsers without speech recognition (Firefox), speaking tasks record audio for playback and are labeled *self-assessed*.
- Guided roleplays are scripted and match key phrases. The UI says so.
- Voices depend on what's installed on the device.
- Levels 3–4 appear on the course map as a roadmap and aren't authored yet.

**Data.** Progress is stored in `localStorage` on the learner's device and can be exported or deleted in Settings. A service worker caches the app for offline use in production builds.
